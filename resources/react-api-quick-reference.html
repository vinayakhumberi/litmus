React API Quick Reference 📋

Every hook, component, and method covered across the React deep-dive topics — one scan, no digging

Grouped by what each API actually controls, not alphabetically — so you can find "the thing that defers a value" without already knowing it's called useDeferredValue. The Lane column is the priority tier the underlying update/read actually gets scheduled in — a lot of these APIs don't have a fixed lane at all; the lane comes from where you call them, and that distinction is itself worth knowing. The "Covered in depth" column links to the topic where the full reasoning, trade-offs, and pitfalls live; this page is a lookup table, not a replacement for reading those.

State & Lifecycle

APIWhat it doesLaneDistinguishing infoCovered in depth
useState Local component state; calling the setter schedules a re-render with the new value. Inherits the caller's context — Sync/Discrete from a direct event handler, Default otherwise, Transition if wrapped in startTransition. Has no fixed priority of its own — the same setter call can land in different lanes depending on where it's called from. react-reconciliation
useReducer Local state managed via a reducer function — same re-render trigger as useState, better suited to complex or interdependent state transitions. Same as useState — determined entirely by calling context. Choosing this over useState is a code-organization decision; it changes nothing about scheduling. react-reconciliation
useRef Mutable value that persists across renders without triggering one when it changes. Also used to hold a reference to a DOM node. N/A — mutating .current never schedules work at all. The only hook here completely invisible to the scheduler; also the mechanism Profiler-style instrumentation uses to survive re-renders without triggering more of them. react-devtools-profiler
useContext Reads a Context's current value. Re-renders the consuming component whenever the context's value reference changes — regardless of which field the component actually reads. Inherits whichever lane the provider's value-changing update was scheduled in. Re-renders on ANY change to the value reference, even fields the component never reads — the classic context-invalidation trap. react-reconciliation
useEffect Runs a side effect after the commit is painted to the screen — asynchronous, doesn't block the browser's paint. Not lane-based — scheduled as a "passive effect" asynchronously after commit, via the same MessageChannel-based scheduler. Any setState called inside it starts a brand-new update with its own, independent lane. react-reconciliation
useLayoutEffect Same as useEffect, but runs synchronously after commit, before the browser paints. Use only for measurements/DOM reads that must happen before the user sees a frame — it blocks paint until it finishes. Runs inside the synchronous commit phase — blocks the browser from painting regardless of what lane the triggering render was in. The one hook here that can single-handedly cause jank on its own, since its work can't be deferred or interrupted. react-reconciliation

Memoization

APIWhat it doesLaneDistinguishing infoCovered in depth
useMemo Caches a computed value between renders, keyed by a dependency array compared with Object.is. Only worth it for genuinely expensive computations — it has its own bookkeeping cost. N/A — resolved synchronously within whatever render is currently executing; schedules nothing of its own. The comparison itself has a real cost paid on every render, even the ones where it hits cache — a wrong trade if the cached work was cheap to begin with. react-memoization
useCallback Caches a function reference between renders. Literally useMemo(() => fn, deps) — exists specifically to stabilize callback props passed to memoized children. N/A — same as useMemo, since it is useMemo under the hood. Caches the reference only, not behavior — the closure still captures whatever was in scope at creation, which is why wrong deps cause stale-closure bugs, not just missed optimizations. react-memoization
React.memo Wraps a component; skips its re-render when triggered by a parent if every prop is shallow-equal to the previous render. Has no effect on re-renders caused by the component's own state or context. N/A — a bailout check performed during reconciliation, not a scheduled update. Only guards against parent-triggered re-renders; zero effect on re-renders from the component's own state or a context it consumes. react-memoization

Concurrent Rendering

APIWhat it doesLaneDistinguishing infoCovered in depth
useTransition Returns [isPending, startTransition] — marks the state updates called inside startTransition as low-priority, and exposes a pending flag tied to the actual commit. Transition lane — one of several transition-lane bitmask slots, so unrelated transitions don't needlessly block each other. Only covers setState calls made synchronously inside the callback — anything after an await needs its own separate startTransition call. react-18-features
startTransition The standalone version of useTransition's setter, without the isPending flag. Only affects setState calls made synchronously inside its callback — not anything after an await. Transition lane — identical scheduling behavior to useTransition's setter. Usable outside components/hooks entirely (class components, vanilla event handlers) — useTransition can't be. react-18-features
useDeferredValue Returns a "lagging" copy of a value you don't own the setter for (a prop, context, or store value) — React updates it at low priority instead of you having to wrap a setState call yourself. The immediately-returned old value comes from whatever lane is currently rendering; the "catch-up" re-render to the new value is scheduled in a Transition lane. No isPending flag — detect staleness yourself by comparing value !== deferredValue. react-18-features
Suspense Declarative boundary that shows a fallback while a subtree "suspends" (throws a promise) — a lazy import, or async data. Only avoids a fallback flash if the triggering update is wrapped in a transition. Not a lane itself — the retry render after the promise resolves uses whatever lane fits the resolution, usually Default unless the original trigger was a transition. Whether the fallback flashes or the old UI stays visible with isPending depends entirely on the triggering update's lane — Suspense doesn't decide this on its own. react-18-features, react-reconciliation
React.lazy Lazily loads a component's module, suspending the nearest Suspense boundary until it resolves — the canonical example of a component "suspending." Same as Suspense — the retry lane depends on the triggering context, not on React.lazy itself. The simplest way to trigger a suspend — good mental-model anchor for how data-fetching libraries suspend too. react-reconciliation

External State & Diagnostics

APIWhat it doesLaneDistinguishing infoCovered in depth
useSyncExternalStore Subscribes a component to a non-React store (Redux, Zustand, a custom store) with a guarantee against "tearing" — every component reading the store during the same concurrent render sees a consistent snapshot, even across interrupted/resumed work. Deliberately not lane-based for the read itself — forces a synchronous, consistent snapshot regardless of what lane the surrounding render is in, specifically to prevent tearing. The correct primitive for any external store used inside an app that has adopted concurrent features — direct getState() reads in render are a real correctness bug once concurrency is in play, not just a style issue. react-reconciliation, react-memoization
Profiler The public component/API DevTools' own Profiler tab is built on. Wraps a subtree and reports actualDuration (real cost this commit) and baseDuration (worst-case cost with no memoization) per commit via onRender. N/A — pure instrumentation, has no effect on scheduling. onRender fires for a wrapped boundary even when its subtree bails out via memo — that's how gray ("bailed") bars in the real DevTools Profiler are possible at all. react-devtools-profiler
Fragment Groups a list of children without adding an extra wrapping DOM node. Not performance-related — purely a composition tool. N/A — no rendering or scheduling behavior of its own at all. Included here only because it shows up in code examples across the other docs, not because it has anything to do with performance. react-devtools-profiler (code examples)
