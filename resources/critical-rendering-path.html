2. Script Loading Race — Blocking vs Async vs Defer

JavaScript is single-threaded. Fetching a script happens off the main thread — the browser's network stack handles downloads in parallel with everything else. Executing it does not — execution always runs on the exact same main thread as HTML parsing, so the moment any script's code actually runs, parsing cannot also be running. Nothing in this race uses a separate thread; the three attributes only change when the fetch starts and when execution is allowed to interrupt parsing.

Legend for the top bar: blue = parser actively advancing. orange = parser cannot advance — either fully stalled waiting on a blocking script's fetch and execution, or very briefly interrupted by a script whose execution just became ready to run.

3. The Preload Scanner Looks Ahead

The main parser and the preload scanner are two separate passes over the same markup. When the main parser is stuck waiting on a blocking script, the preload scanner keeps going — it just can't execute anything, only discover and start fetching it.

<head>👷 parser⚡ scanner
<link rel="stylesheet" href="theme.css">fetch started
<script src="analytics.js"></script>fetch started
<script src="app.js"></script>fetch started
</head>
<body>
<img src="hero.jpg">fetch started
</body>

Click Run — the ⚡ scanner cursor will reach app.js and hero.jpg and start fetching them while the 👷 main parser is still stuck waiting on analytics.js to download and execute.
