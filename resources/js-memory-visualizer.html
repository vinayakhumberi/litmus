Every running execution context actually tracks two environment pointers: VariableEnvironment (where var and function declarations live — fixed for the whole function/script call) and LexicalEnvironment (resolves identifiers right now — can temporarily point somewhere else, e.g. inside a block or a let-based for loop). For a simple function body with no nested blocks, they're the same Environment Record the entire time, so this visualizer labels that one box "Lexical Environment = Variable Environment." They only genuinely split into two different records in Example 4, where each loop iteration gets its own LexicalEnvironment while VariableEnvironment stays put — that's the one case worth memorizing.
